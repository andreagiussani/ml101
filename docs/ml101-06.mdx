Two ideas organize this lesson. **A decision tree divides the feature space into regions. Gradient boosting builds a predictive function by adding trees that correct what the current model still gets wrong.** We will use the same small student-grade example throughout, then generalize the mathematics.

<h2 id="trees">01 · Trees turn questions into regions</h2>

Suppose we want to predict a student’s final grade G3, on a scale from zero to twenty. Begin with four **synthetic** observations: A studies two hours and scores 7; B studies three hours and scores 10; C studies seven hours and scores 16; D studies eight hours and scores 15. The values are chosen to make the algorithm visible, not to claim that more study time causes higher grades.

A decision tree asks a question such as **“Is study time at most five hours?”** That one question divides the data into two leaves. In two dimensions, each threshold creates an axis-aligned boundary; recursive splits tile the feature space into rectangular regions. A tree can capture interactions this way without us writing interaction terms by hand.

### What prediction belongs in a leaf?

For squared-error regression, the best constant prediction in a region R is its sample mean. We can derive it by differentiating the sum of squared residuals with respect to the constant c:

Our leaf for A and B therefore predicts (7 + 10) / 2 = <strong>8.5</strong>. The leaf for C and D predicts (16 + 15) / 2 = <strong>15.5</strong>. A regression tree is a piecewise-constant function:

### Let CART search for a useful question

At a node, CART considers candidate features j and thresholds s. For each candidate it calculates the error in the left and right children after assigning each child its own mean. The greedy split chooses the largest immediate reduction:

<SplitObjectiveEquation />

It then repeats inside the new nodes until a stopping rule is reached. This is a local search: the best next split does not guarantee the globally best complete tree.

Use the slider to move the question and see each leaf’s mean and squared error change. At the five-hour split, the decision stump—a tree with one question and two leaves—reduces SSE from 54 to 5.

<TreeSplitLab />

The split after B is especially good here: both feature regions are internally tight. But one impressive split does not make a deep tree trustworthy. More questions create smaller leaves; training error can fall while predictions become more sensitive to which observations happened to enter the sample.

### Classification trees measure mixed labels

For a binary target, a leaf can predict the share p of class 1. CART can compare candidate splits using Gini impurity or entropy. Both are zero for a pure node and largest when the classes are evenly mixed.

<ClassificationImpurityLab />

### Tree size is regularization

A shallow tree uses a few broad regions. It is easier to explain and often more stable, but can miss structure. A deep tree can represent finer patterns, but small leaves make its predictions unstable. Maximum depth, minimum leaf size, and pruning are model-complexity choices, much like regularization in linear models.

Cost-complexity pruning scores a subtree by its fit plus a charge for its leaves:

<PruningEquation />

At α = 0, leaves are free. Increase α and a split must earn its place by reducing error enough to justify the extra leaf. Use validation or cross-validation on development data to choose depth, minimum leaf size, or α; keep the final test set outside that search.

## The pivot · many trees can cooperate

A tree is a complete model by itself. **Bagging** trains trees in parallel on bootstrap samples and averages their predictions, often reducing the variance of unstable trees. Random forests add random feature selection. **Boosting** follows a different plan: it fits trees in sequence, and each new tree depends on the current ensemble’s remaining errors.

<h2 id="boosting">02 · Boosting builds by correction</h2>

The four students’ grades average to 12. Under squared error, that is the best constant prediction before we know anything else:

<InitialPredictionEquation />

Every student gets the same starting prediction. Residuals tell us which direction each prediction needs to move.

| Student | Study hours | Grade y | Starting F₀ | Residual y − F₀ |
|:--|--:|--:|--:|--:|
| A | 2 | 7 | 12 | −5 |
| B | 3 | 10 | 12 | −2 |
| C | 7 | 16 | 12 | +4 |
| D | 8 | 15 | 12 | +3 |

The correction tree uses the same five-hour split. The left leaf’s average residual is (−5 − 2) / 2 = −3.5; the right’s is (4 + 3) / 2 = +3.5. These are **updates**, not new final predictions. With learning rate η = 0.5, the first predictions become 10.25 and 13.75.

<BoostingLab />

The plot shows two views of this fixed-split teaching example. As M grows, each leaf prediction approaches its own sample mean. Training SSE falls from 54 toward 5; it cannot go below 5 while we keep this particular split, because students within each leaf still differ. Changing η changes how quickly those corrections accumulate.

### Why are residuals the right direction?

For half squared-error loss, differentiate with respect to the current prediction F:

<SquaredLossEquation />

So fitting a regression tree to residuals is exactly fitting it to the negative gradient of the loss with respect to the current predictions. The next tree approximates a descent direction in function space. That is the “gradient” in gradient boosting.

For another differentiable loss, the algorithm computes **pseudo-responses**—negative loss gradients at the current predictions—then fits a small regression tree to them. Leaf updates may need a loss-specific optimization; they are not always simply the mean pseudo-response.

<LogisticGradientCard />

### Three knobs shape the ensemble

Tree depth or number of leaves controls the complexity of each correction. The learning rate η controls the size of every update. The number of trees M controls how many updates are added. A smaller learning rate often needs more trees to reach a similar training fit; these settings interact and should be selected with development data.

<EarlyStoppingLab />

Early stopping chooses the number of trees using a validation set or cross-validation. Training loss can keep falling after validation performance has stopped improving. The final test set must not pick M, tune η, or decide which version to report.

<div className={styles.bridge}><strong>Keep the distinction clear.</strong> AdaBoost and gradient boosting share a sequential “improve the current model” philosophy, but their standard algorithms differ. Classical AdaBoost reweights examples and is associated with exponential loss; gradient boosting fits negative gradients of a chosen differentiable loss.</div>

### A prediction rule is not a causal explanation

If a tree often splits on study time, that means the feature helps distinguish observed grade patterns in this dataset. It does not show that forcing a student to study one more hour will cause a particular grade increase. Prediction describes associations useful for forecasting; a causal claim needs an identification strategy or experimental design.

## Leave with these contrasts

<ul className={styles.recap}>
  <li><strong>A tree partitions.</strong> Each leaf predicts a mean or class probability; greedy splits reduce local loss or impurity.</li>
  <li><strong>Complexity has a price.</strong> Depth, leaf size, pruning, and early stopping control how much the model can fit.</li>
  <li><strong>Boosting adds.</strong> Each new small tree approximates a correction to the current ensemble, guided by a loss gradient.</li>
</ul>
